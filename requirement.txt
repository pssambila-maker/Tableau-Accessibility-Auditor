This is a comprehensive technical build plan for your Tableau Accessibility Compliance Auditor.

We will name this application "TabAccess". It will be a Python-based tool with a Streamlit interface that acts as a "gatekeeper," ensuring dashboards meet standards before they are widely promoted.

The Architecture
The app consists of three distinct modules:

The Parser (Module A): Reads the workbook code (.twb/XML) to check structure.

The Scanner (Module B): Uses Computer Vision on dashboard screenshots to check contrast.

The Interface (Module C): A Streamlit web app for users to interact with the tool.

Phase 2: Build Module A (The Structure Validator)
Goal: Verify "Focus Order" and "Alt Text" by reading the raw code of the workbook.

The Logic (core/parser.py):

Handle .twbx files: A .twbx is just a zip file. Your script must unzip it to find the .twb (XML) file inside.

Check Focus Order:

Parse the XML tree.

Locate the <zones> section (this defines the layout).

Extract the id attributes.

Rule: If IDs are random (e.g., 45, 12, 110), flag as "Potential Fail." If sequential (1, 2, 3), flag as "Pass."

Check Alt Text:

Search for <worksheet> tags.

Look for the <caption> attribute or specific accessibility tags (Tableau's XML changes often, so you look for the text descriptions).

Rule: If caption is empty or missing, flag as "Fail."

Phase 3: Build Module B (The Visual Validator)
Goal: Verify "Color Contrast" using a screenshot, simulating a user's view.

The Logic (core/scanner.py):

Fetch Image: Use the tableauserverclient (TSC) to authenticate and download a high-res PNG of the view.

Extract Colors: Use OpenCV (K-Means Clustering) to find the top 5 dominant colors in the image.

Why? You don't need to check every pixel. You need the "Palette."

Run the Math: Pass these colors to your contrast.py script (the math I gave you earlier).

Rule: If the contrast between the dominant background color and the dominant text color is < 4.5, flag as "Fail."
